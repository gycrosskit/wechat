## 本地行为检查

以下命令从仓库根目录执行。配置`ANDROID_HOME`与可运行Gradle的JDK；Kotlin/Native测试需要macOS、Xcode及iOS Simulator运行环境。Node测试转译真实ArkTS源码并使用受控SDK替身，`TYPESCRIPT_PATH`可指定已有TypeScript模块。

```sh
bash gradlew :wechat-core:testDebugUnitTest :wechat-core:jvmTest --max-workers=1
node tests/wechat.cjs
node tests/preferences-store.cjs
python3 tests/swift-receipt.py
python3 tests/swift-callback.py
mkdir -p build/swift-session
swiftc iosApp/Sources/GycWechatNative/WechatSession.swift verification/swift/main.swift -o build/swift-session/check
build/swift-session/check
```

URL 回归执行完整生产 Client 与 Session，保留 SHA-256 来源记录；仅 SDK 和无关缩略图转换替身。覆盖两个入口的同步/异步 clear 失败重试、in-flight 去重、invalid state、SDK false、旧代理隔离、重入及无 transaction 的分享/转账去重，不证明真实微信回跳。

只运行受影响目标；需要确认本轮真实执行时加`--rerun-tasks`，不要把`UP-TO-DATE`算成新执行。平台测试结果XML位于`wechat-core/build/test-results/`。这些测试不调用真实分享、认证、拨号或定位业务。

## 原生产物与独立消费

HarmonyOS工具链需要DevEco SDK、ohpm与hvigorw。在`ohos/`目录执行：

```sh
ohpm install --all
hvigorw --mode module -p module=WechatNative@default -p product=default assembleHar --no-daemon
```

安装与公开API消费工程按[接入指南](接入指南.md)和[README](../README.md)执行。构建/本地HAR消费不等于OHPM Registry或本版远程消费。Maven、Swift/Pod与HAR按各自版本验证。

## Kuikly receiver 源码验证（2026-10-09）

新增 Swift receiver 行为测试执行实际receiver源码，以可控Native/Renderer边界验证同意/受理/回执边界、跨Renderer隔离、取消失败、重复invalidate、排队调用、资源创建时失效和基类dealloc清理；不是SDK业务或设备证明：

```sh
python3 verification/swift-kuikly/verify.py
```

Android新增receiver测试包含在 `:wechat-core:testDebugUnitTest`；真实Kuikly AAR与厂商SDK编译为 `:wechat-kuikly:compileReleaseKotlinAndroid`。iOS发送端目标使用 `:wechat-kuikly:compileKotlinIosArm64` / `compileKotlinIosSimulatorArm64`。真实Swift receiver必须另以可选Pod/Kuikly依赖真实OpenKuiklyIOSRender2.28.0做xcodebuild/链接；替身Swift tests不能替代它。公开Maven、GitPod/SwiftPackage、HAR与设备业务分别留证，具体发布与远程验收结果见[对应 Release](https://github.com/gycrosskit/wechat/releases/tag/0.1.8)。

真实可选Pod验证使用仓库内同字节共用脚本（macOS/Xcode/CocoaPods），只安装一次SDK并构建包含receiver的Pod target：

```sh
bash scripts/ci-build-kuikly-render.sh "$TMPDIR/wechat-kuikly-sdk" GycWechatNative/Kuikly
```

新Native receiver消费者必须显式 `-PverifyNativeModule=true`。旧发布版本仍关闭此flag，只消费原core和OHOS模块；新Release门禁从0.1.8开始启用新probe。开发本地staging消费者与公开远程消费者的结果分开报告。

Release consumer 在启用 receiver probe 时，通过 `-PkuiklyRenderFrameworkDir=/absolute/Products` 链接真实 OpenKuiklyIOSRender。CI 先调用同一个 Pod/SDK build helper，再把返回 Products 目录传给 KMP framework link；旧 tag 不启用新 probe。

真实 Pod build 后，可执行 `python3 verification/swift-kuikly/verify-public-api.py /absolute/Products` 独立 import 已构建的 Native framework，检查 factory/provider、register、typed hrv_call、invalidate 公开导出；该检查不编译 receiver 源码进入消费侧，也不调用厂商业务。
