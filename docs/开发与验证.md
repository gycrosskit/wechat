# 微信开发与验证

## 2026-10-04 本地取消确认候选

本轮尚未提交或发布。取消只有原生同步清除可信 pending 成功后才交付 `CANCELLED`；失败与未知 ID 不宣告原提交终态。SDK 已受理但后续图像清理抛错时，内部 `pending` ack 保留原 owner，Kotlin 不转为 `REQUESTED`、成功或 `FAILED`。本协议须同时升级 Kuikly Maven 与 HAR 至 0.1.4，现有远程 0.1.3 不包含该修复。

真实 ArkTS Client/Module 的 Node SDK 替身覆盖清除失败后迟回执、取消重试、未知/其他 owner/已完成 ID、成功取消后迟提交结果、SDK 受理后资源清理失败、销毁清除失败后 framework 清理与新 owner 恢复。Preferences 测试覆盖缓存恢复与回滚二次异常不覆盖原错误；异常不能证明磁盘未写。Swift Foundation Session 同步取消失败测试通过。

`ANDROID_HOME=<Android SDK> bash gradlew :wechat-core:jvmTest :wechat-kuikly:compileKotlinOhosArm64 --max-workers=1 --no-parallel --console=plain` 通过：10 个 JVM 测试零失败，包含实际 Kotlin `WechatModule` 的 5 项 transport 探针。薄 stub 依照锁定 Kuikly 2.28.0 sources 中 `Module.toNative` 的 keep-alive 返回值与 `GlobalFunctions.invokeFunction` 自动释放契约，不复制取消实现；覆盖同步 ack、失败/无 pending/成功 ack、重试与 dispose 前排队 ack。

同版本地 HAR `WechatNative@default assembleHar --no-daemon` 通过（29 tasks，20 执行）。首次 ArkTS 编译拒绝任意类型的 throw，改为 `throw error as Error` 后通过，仍保留原始异常对象。日志在忽略目录 `build/remote-library-review/`。这些验证不代表真实微信页面、存储故障、SDK 交付或设备验收通过。

## 本地验证

使用 JDK 21，`ANDROID_HOME` 指向本机 Android SDK。构建时固定 `--max-workers=1`，没有真实微信操作。

```sh
bash gradlew :wechat-core:compileDebugKotlinAndroid :wechat-core:jvmTest \
  :wechat-core:linkDebugFrameworkIosSimulatorArm64 :wechat-core:compileKotlinOhosArm64 \
  :wechat-kuikly:compileKotlinOhosArm64 --max-workers=1 --no-daemon
node tests/wechat.cjs
# classes.jar 从已安装 Android SDK 6.8.34 AAR 解包；android.jar 使用本机 Android SDK。
# 仅调用 SDK checkArgs，不发请求；厂商旧 stackmap 需要此 JVM 检查选项。
java -Xverify:none -ea --class-path "<classes.jar>:<android.jar>" tests/AndroidSdkCheck.java
xcrun swiftc iosApp/Sources/GycWechatNative/WechatSession.swift verification/swift/main.swift -o build/swift-check
build/swift-check
# 构建源码为本地 Maven 文件仓库，仅供独立消费者验证：
bash gradlew :wechat-core:publishToMavenLocal :wechat-kuikly:publishToMavenLocal \
  -Dmaven.repo.local="$PWD/verification/maven" --max-workers=1 --no-daemon
bash gradlew -p verification/gradle -PwechatMavenRepo="$PWD/verification/maven" \
  compileDebugKotlinAndroid linkDebugFrameworkIosSimulatorArm64 compileKotlinOhosArm64 \
  --max-workers=1 --no-daemon
# DevEco 环境：
cd ohos && ohpm install --all
hvigorw --mode module -p module=WechatNative@default -p product=default assembleHar --no-daemon
```

Swift Package 构建需向 `xcodebuild` 提供对应官方 XCFramework slice 的 `FRAMEWORK_SEARCH_PATHS` 和 `OTHER_SWIFT_FLAGS='-F <slice-directory>'`，使用 `-jobs 1 CODE_SIGNING_ALLOWED=NO`。独立 Swift consumer 位于 `verification/swift-consumer`；独立 HAR consumer 位于 `verification/ohos`，安装生产出来的本地 HAR，再 `assembleHar`。

实际结果见 [VALIDATION.md](../VALIDATION.md)。真实客户端安装/未安装、OAuth 返回、好友/朋友圈 UI、Universal Link 和 OHOS 签名回跳均未做设备验收；没有真实登录、支付、转账或发送分享。

## SDK 契约依据

商家转账契约参考官方 [Android 商家转账](https://pay.wechatpay.cn/doc/v3/merchant/4012719576)、[iOS 商家转账](https://pay.wechatpay.cn/doc/v3/merchant/4012719578) 与 [转账参数常见问题](https://pay.wechatpay.cn/doc/v3/merchant/4013778940)：SDK 最低版本、Android 版本门槛、业务类型、参数原样 URL 编码、页面回执非资金终态。

宿主登记与平台配置参考微信开放平台的 [Android 接入](https://developers.weixin.qq.com/doc/oplatform/Mobile_App/Access_Guide/Android.html)、[iOS 接入](https://developers.weixin.qq.com/doc/oplatform/Mobile_App/Access_Guide/iOS.html)、[OHOS 接入](https://developers.weixin.qq.com/doc/oplatform/Mobile_App/Access_Guide/ohos.html) 和 [OAuth 指引](https://developers.weixin.qq.com/doc/oplatform/Mobile_App/WeChat_Login/Development_Guide.html)。组件回执边界依据实际安装的官方 SDK Header/API 核对，不能据通用支持查询推断未知专用场景的客户端版本能力。

分享契约以实际安装 SDK 为准：Android 6.8.34 AAR 的 `WXImageObject.checkArgs` 为 26214400 字节；`SendMessageToWX.Req.checkArgs` 在 scene=3 同时要求 userOpenId 与 BaseReq.openId；Build 指定联系人门槛 620824064、25M 图片门槛 620889088。iOS 2.0.7 `WXApiObject.h` 的 imageData 为 25M、title 为 512 字节、description 为 1K，BaseResp 没有 transaction。OHOS 1.0.23 `.d.ets`/实现仅公开 SESSION/TIMELINE，并声明 title/description 字节约束。不能据此推断未公开的专用版本能力。
