## 公开 API 组

当前未发布源码把通用协议解释留在组件，宿主不再复制：

- Kotlin `WechatReceipt.routingRequestId` 只给出可路由 ID，分享候选仍保留 `SINGLE_PENDING`，不提升证据级别。
- `WechatReceipt.transferPageStatus` / `WechatTransferPageStatus.from(errorCode, pageResult)` 统一确认页结果，`SUCCESS` 不表示到账；宿主负责本地化、刷新与业务完成。
- `WechatModule.supportsTransferReceiptOwnership` 提供平台事实：Android/OHOS 为 true，iOS 为 false；JVM 仅测试核心，无原生能力。宿主无需再次硬编码平台分支。
- `WechatModule.shareImageBase64(..., maximumBytes)` 接收纯 Base64 或 Data URL，规范空白/补位并按解码后长度检查上限，直接传原生解码；不在公共层构造图片 ByteArray 再编码。默认厂商上限 25 MiB，宿主可以传更小上限；字节数组原入口保留。
- OHOS Native Module 的可选 `clientProvider` 只在显式 listen 和其后续请求取配置，失败后保留监听意图并恢复；取消/释放不触发 SDK 初始化。未 listen 的 Module 不提交，原生 Client 直接 API 不受 Module 监听约束。

本次重复图片分享合同要求使用顶部列出的配套新版本；旧版本不具备该行为。

- 未发布 `WechatModule.awaitSubmission(requestId, kind) { send() }`：三端共用的 30 秒提交等待；既有 callback API 保留。SDK 受理后结束等待，最终回执另交 listener；不增加全局发送锁。
- `WechatClient.authorize` / `shareImage` / `shareWebPage` / `openMerchantTransfer` / `cancel`；监听器`onSubmitted`和`onReceipt`分开发送受理与SDK回执。
- 平台回跳：Android handleIntent、iOS handleOpenURL/handleUniversalLink、OHOS forwardWant/handleWant；可信store恢复只消费厂商已验证回执。
- 平台attach/detach或add/removeListener，以及三端 WechatModule.dispose；client/owner与页面生命周期不同。

## 按类型当前轮合同（未发布）

登录、分享、转账各有当前轮，不设置公共发送等待，也不保留已受理请求的历史关联集合。图片与网页属于同一分享类型。参数或 SDK 条件不满足时报告本次失败；同类型新请求生效后，旧轮仅以本地 `CANCELLED` 结束，不能伪造 SDK `errorCode=-2` 回执。

- 新轮先安装，旧轮再通知；旧取消、超时、异步图片处理、SDK 提交结果与可识别的迟回执只能处理匹配 ID。通知回调重入第三轮后，第二轮不得继续发 SDK。
- Android/OHOS 按当前 transaction、kind、OAuth state 消费一次。三端新 journal 仅保存 OAuth；save(new) 成功才替换旧授权，save/clear 失败不得静默交付。Android/OHOS 仍可消费旧版可信非 OAuth journal，不能因此清除新的授权记录。
- iOS OAuth 以 state 精确匹配；分享保留 `SINGLE_PENDING/UNATTRIBUTED`。图片受理、收到图片回执、已发送分享取消或重叠分享后，候选能力仍按 SDK 限制降级。转账没有可靠请求标识，受理后不保留无用候选，继续交付无法归属的原回执通道；不能据此证明到账。
- 三端 Native receiver 将已受理旧轮的替换通知作为 listen 控制事件 `{requestId,status:"cancelled"}`；未完成提交则直接结束原提交回调。公共 Module 同一入口清理本轮 callback/协程等待，不生成业务回执。页面释放仅取消自己持有的 ID。
- `awaitSubmission` 的 30 秒只限制 SDK 提交等待，不锁住其他请求；收到早到的匹配回执可完成该提交。返回 App 无回执不猜测成功或取消，下一次点击仍可新发起。宿主不应再增加等待 SDK 最终结果的全局队列或重复计时。

当前分支验证入口见[本地行为检查](开发与验证.md#本地行为检查)。源码、真实 SDK 编译、完整消费与真机业务分别验收，未发布源码不能作为已发布版本能力。

## 当前候选：提交等待由 wechat-kuikly 统一管理

`WechatModule.awaitSubmission(requestId, kind) { ... }` 为现有 callback API 增加可取消 suspend 入口，等待上限 30 秒。每个请求单独等待，不增加全局 busy 锁；REQUESTED 立即结束提交等待，不等待最终微信回执。最终回执继续交 listener，不能当作到账或任务完成证明。

取消/超时只转交本次 ID；旧回执、错误 kind、旧 cancel 不能完成或清理新请求。真实早到回执仅在组件验证的 ID/类型或已有 SINGLE_PENDING 分享候选下结束对应提交，不提升回执可信度。dispose 取消本页等待和回调；SDK 受理回执已到但协程尚未恢复时，也不得在销毁后交付 REQUESTED。不创建第二个 SDK client。

OAuth 等待仍属于授权页生命周期：宿主在重试、切换方式、撤销同意与离页时取消本次 ID，并提供有界期限；组件保留 state/transaction 校验。发送互斥、提交协程、最终回执关联与业务完成是不同状态，不能把前台恢复当作成功或全局清空等待。

验证需包含无最终回执连续提交、未登录返回后重试、旧超时/取消/回执与后继请求交错。组件已有 [OHOS 行为测试](../tests/wechat.cjs)、[Swift 回跳测试](../tests/swift-callback.py)与 [Swift receiver 测试](../verification/swift-kuikly/verify.py)分别约束 SDK 和 Renderer 边界；宿主公共适配器测试另核对当前候选 Module。受控 transport/计时不替代三端真机。
