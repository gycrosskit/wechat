# wechat 功能与平台差异

版本组合：Maven 0.1.7、Swift Package / Git Pod native-0.1.6（Pod内部0.1.6）、HAR 0.1.6。本轮从源码 `1400ca113e44a1118fd33c13cd93420e8c16db32` 修复 UTF-16 参数边界与监听回放；旧 Maven 0.1.6 / native-0.1.5 / HAR 0.1.5 保持不变。各渠道最终状态见 [Release](https://github.com/gycrosskit/wechat/releases/tag/0.1.7)，源码、受控测试、真实 SDK 编译与设备业务分别见下表。

## 产物与职责

| 模块/产品 | 实际职责 |
|---|---|
| `wechat-core` | WechatClient / Listener / Receipt / pending模型、Android client与IosWechatClient bridge；无微信业务页面。 |
| `wechat-kuikly` | 仅ohosArm64 WechatModule（GycWechat），页面请求owner与回调清理；Android/iOS两套UI走宿主注入native client。 |
| `GycWechatNative` | iOS15+ Swift Package/Git Pod源码；官方WechatOpenSDK-XCFramework2.0.7，SPM不自带binary，宿主负责链接。 |
| `@gycrosskit/wechat-native` | API22 HAR，WechatClient、WechatPreferencesRequestStore、WechatModule，@tencent/wechat_open_sdk1.0.23。 |

构建边界：[core构建](../wechat-core/build.gradle.kts)、[Kuikly构建](../wechat-kuikly/build.gradle.kts)、[模块清单](../settings.gradle.kts)、[OHOS SDK配置](../ohos/build-profile.json5)。

除上表明确的 UI 入口外，本库没有独立 CMP 页面模块。Android/iOS 可由宿主原生适配把同一能力供 CMP 与 Kuikly 使用；“可注入两套UI”不代表库自动完成宿主接线、同名 Renderer 注册或品牌验收。

## 公开 API 组

- `WechatClient.authorize` / `shareImage` / `shareWebPage` / `openMerchantTransfer` / `cancel`；监听器`onSubmitted`和`onReceipt`分开发送受理与SDK回执。
- 平台回跳：Android handleIntent、iOS handleOpenURL/handleUniversalLink、OHOS forwardWant/handleWant；可信store恢复只消费厂商已验证回执。
- 平台attach/detach或add/removeListener，以及OHOS WechatModule.dispose；client/owner与页面生命周期不同。

## API 合同与差异分类

| 分类 | 具体输入 / OS / SDK边界 | 调用方应如何处理 |
|---|---|---|
| 厂商限制 | Android SDK6.8.34；iOS2.0.7；OHOS1.0.23，Android API24+/i15+/Otarget22compatible22。 | iOS用WXSceneSpecifiedSession/toUserOpenId/openID支持指定好友；OHOS官方包无公开recipient协议，UNSUPPORTED，不能降级普通分享。 |
| 宿主职责 | 指定联系人公共入口需WechatScene.SESSION（Swift层为.session）、可信recipientID及当前AppID下senderOpenID。 | 开放平台登记/签名、UniversalLink/AASA、回跳、品牌AppID、账号与转账服务端参数由宿主原样提供，库不猜当前账号。 |
| 组件边界 | 网页URL10KiB UTF8；title256/description512 UTF16码元，再限512/1024UTF8字节。 | 三端helper统一截断且不切surrogate；不保证组合字符/ZWJ完整grapheme。图片PNG/JPEG输入最大25MiB，压缩/缩略图限额由SDK与原生实现管理。 |
| 厂商限制 | A/O transaction+kind及OAuth state验证；iOAuth state验证，share BaseResp无transaction。 | i分享requestId=nil、candidateRequestId/SINGLE_PENDING仅本地单笔候选；转账UNATTRIBUTED与页面success均不能证明资金到账。 |
| 组件边界 | iOS已交SDK的share取消后quarantine，后续share UNSUPPORTED。 | 没有可验证身份的旧回执不能安全归属新任务；不能同进程重建client绕过。OAuth/transfer仍可用。 |
| 宿主职责 | requestId最长128个UTF-16单元且生命周期不复用；可信OAuth state最长256个UTF-16单元；可信同步原子journal在发送前保存、消费/取消前清除。 | 不能从外部Intent/Want/URL恢复资格。A/O可恢复对应pending，i仅恢复OAuth；清除失败保留owner，不假终态。 |
| 组件生命周期 | attach/addListener逐条移出缓冲；detach/removeListener或替换注册立即停止旧owner回放，余项保留给后继匹配注册。 | OHOS实时回执也按投递开始时的注册快照交付，回调中重注册不会重复消费同一回执。 |
| 未验收 | 真实微信授权/分享/支付、指定账号关系、回跳及多品牌后台登记。 | SDK真实链接/状态机mock不证明微信业务被受理或钱到账；各渠道实际状态见顶部版本发布记录。 |
