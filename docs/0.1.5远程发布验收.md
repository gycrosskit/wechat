# 0.1.5 线程边界修复验收

2026-10-05，[修复 PR #13](https://github.com/gycrosskit/wechat/pull/13) 已合并；不可变 tag `0.1.5` 对应合并提交 `bc6b5d1c9ab13ef5730f91663a270432398d1950`。[GitHub Release](https://github.com/gycrosskit/wechat/releases/tag/0.1.5) 为 prerelease，Maven 归档已发布，旧 tag 与资产未覆盖。

## 修复与源码验证

Android 构造不调用 SDK；Unit 请求、监听与取消自带 Main 边界，SDK、可信 store、状态与回执串行到 Main。图片解码仍由专用 executor 执行，SDK 发送回 Main。旧同步 Boolean `handleIntent` 保持 Main-only，后台使用 Result callback 重载；Unit 返回不代表 SDK 受理，宿主等 `onSubmitted(REQUESTED)`。取消、清除失败与迟回执保留原请求 owner，回执不是业务成功或到账凭据。

本轮 22 项 Android（17 项实际 client、5 项共享）和 10 项 JVM 测试通过，failure/error/skipped 均为 0；Android/OHOS 编译与独立源码 composite API 消费通过。这些本地结果不代表新 Maven 独立远程消费或真实微信客户端已验收。

## 消费与配套渠道

首次独立 Android 消费未通过：解析先从 Eazy 仓库取得 Kuikly metadata，随后该镜像对应 AAR 的 HEAD 请求返回 404；不能将此结果归因于新组件 publication 缺失。腾讯 `maven-tencent` 的同坐标 GET 返回 200，实际文件哈希吻合。Eazy 稍后的 GET/HEAD 也返回 200，因此该记录只说明当时镜像 metadata 与 artifact 可用性不一致，不表示永久缺包。安装示例用 `exclusiveContent` 将 `com.tencent.kuikly-open` 固定到腾讯 `maven-tencent`，其他 SDK/插件仓库及组件版本保持；协调者正在按该固定源复验，尚不记录消费通过。

独立远程消费：通过。隔离组件文件与 descriptor 缓存后仅从 JitPack 下载精确版本；Android APK、D8、重复类及版本检查通过；iOS arm64/x64 编译、Simulator static Framework 导出与实际链接、版本检查通过；OHOS 五个组件 core/kuikly 编译及版本检查通过，live 不包含 OHOS 实现。Kuikly 使用腾讯 Maven 的专用 group 路由。没有本地源码、composite、mavenLocal 或 staging 替代远程制品。

兼容组合保持 Maven `0.1.5`、OHOS HAR `0.1.4`、Swift Package/Git Pod `0.1.3`。后两者本轮源码与协议未变，不重新包装或覆盖旧发布；HAR Registry 状态仍按 [0.1.4 记录](0.1.4远程发布验收.md) 单独验收。微信签名回跳、Universal Link、真实页面、存储、取消及业务结果由宿主/用户设备验收，组件编译与制品下载不替代这些结果。
