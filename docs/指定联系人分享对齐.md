# iOS 指定联系人图片分享

2026-10-08，未发布源码；不更改现有 Maven 0.1.5、HAR 0.1.4 或 native-0.1.4 不可变标签。

旧 iOS 实现因未验收兼容性而一律返回 Unsupported，未找到可复现的 SDK 兼容故障证据。现用官方 WechatOpenSDK-XCFramework 2.0.7 已公开 `WXSceneSpecifiedSession = 3`、`SendMessageToWXReq.toUserOpenId`，`BaseReq.openID` 用于发送者账号校验。故在既有 `shareImage` 入口映射这些字段，不升级 SDK，不新增请求状态机。

指定联系人必须使用 Session 且提供同 AppID 的可信双方 openId；空接收者/错误场景为 invalid_content，缺少可信发送者沿 Android 合同为 unsupported。SDK 拒绝为 failed，普通好友/朋友圈保持原路径。接收者与发送者不记录到日志或 pending；回执仍沿原单笔候选/取消隔离合同，不能冒称已证明 transaction 归属。

## 可执行验证

- `python3 tests/swift-receipt.py`：提取实际生产 `shareImage`、请求构造、`onResp` 及真实 Session 执行，检查指定场景/双方 ID/字节、普通两场景、空参数、错误场景、无图/超限、busy、SDK 拒绝重试、取消及迟回执；同时保留 OAuth 空 code 回归。
- `swiftc iosApp/Sources/GycWechatNative/WechatSession.swift verification/swift/main.swift -o /tmp/gyc-wechat-session && /tmp/gyc-wechat-session`：真实 Session 回归。
- 使用 Xcode iphoneos SDK 和实际 2.0.7 官方 device Framework，对两个生产 Swift 文件执行 `swiftc -typecheck -target arm64-apple-ios15.0` 已通过。替身回归不代替此 SDK 签名验证。

- 实际官方 device slice 与两个生产 Swift 文件完成 arm64/iOS15 可执行文件最终链接，Mach-O `LC_BUILD_VERSION` 为 IOS、minos 15.0、SDK26.2；显式指定 SDKROOT 后链接日志无警告。该 Probe 未运行 SDK 动作，也不是 mingqi 整 App 验收。

尚未做指定收件人真机发送、微信客户端最低版本/换号/取消交互验收；未发布新远程 Native 包，旧远程版本功能不会自动变化。

## 鸿蒙残留

2026-10-08 官方 OHPM 最新仍是 `@tencent/wechat_open_sdk 1.0.23`，原始 HAR integrity 已校验；其请求只序列化 message/scene，没有独立接收者字段，官方手册仅说明 Session/Timeline。`BaseReq.openId` 不能擅自当接收者，`scene` 接受数字不能证明 scene=3 受客户端支持。当前保留 Unsupported。需腾讯公开/确认协议后再接入，不能用普通分享选择器伪报指定联系人。
